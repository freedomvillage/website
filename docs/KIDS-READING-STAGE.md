The stage requires at least 560px of content width, a viewport wider than 800px and at least 720px tall, plus 280px of usable space between the existing contents and composer. Otherwise the complete original static scenes remain. Reduced motion, no JavaScript and unsupported sticky positioning retain the full static reader. The stage releases before questions and closing actions.

Passive progress changes only decorative frame visibility and `aria-current` on the existing contents. It never moves focus, changes URL/hash/history or announces progress. Explicit native contents links keep their existing focus/hash behavior; Back still restores the Family/Kids question context. Layout qualification updates on size changes, while passive scroll is coalesced into one animation-frame read and changes state only at chapter boundaries.
